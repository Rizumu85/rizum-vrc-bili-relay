## v0.1.30 — 修复失败回滚后的弹幕时间错位

### 修复

- ASS 弹幕资源现在明确保存生成时的源时间起点，避免切换或倍速修改失败后，视频从较新位置恢复、弹幕却继续按旧起点解释。
- 移除只提供文件路径的无时间绑定接口；所有新媒体生产进程在共享 FFmpeg 构造流程中，将当前播放起点与 ASS 原始起点绑定。
- 时间转换仅发生在 ASS 绘制阶段，之后恢复原生产进程时间轴再应用倍速。没有改音频时钟、推流偏移、编解码参数、UI 或配置格式；回滚也不需要重新联网获取弹幕。
- 新增 `ass_bound` 数值诊断：`ass_origin_seconds`、`ass_source_start_seconds`、`ass_offset_seconds`，沿用已有进程编号和日志轮转，不默认记录弹幕正文、路径、Cookie 或推流密钥。

### 实际验证

已读取 Windows FFmpeg 9.0.2 与 Linux FFmpeg 6.1.1 的生产代码测量报告：在 1×、2×、0.5× 下，真正触发会话切换失败和倍速修改失败，再由原有会话代码执行回滚。通过录制画面中的源时间标记确认，原视频第 31 秒的弹幕在约 31.00–31.17 秒出现，而不是因复用旧 ASS 起点而延迟数秒。像素读数有 1/6 秒标记精度及 10 fps 采样限制，不宣称逐帧绝对精确。

六组观察中，旧 ASS 在恢复后仍存在，废弃的新文件被清理，停止后旧文件也被清理；每组外层 publisher 保持同一进程，音视频 DTS 倒退计数均为 0。原有 720p/1080p 视频及直播弹幕像素测量同时保留。随 Release 附上 `ass-clock.json`、其他媒体报告和校验记录，详情见 `docs/ass-clock-audit.md`。

故意制造的 HTTP 404、无效 ASS，以及本地录制器关闭时的 I/O 告警仍保留在证据中，不用“退出码为 0”冒充所有行为正确。没有运行功能测试套件，没有在真实 B 站账号、VRCDN 或 VRChat 世界中做端到端验收。本版只修复这项已确认的时间绑定问题，不表示全仓问题已清零。

### 下载与升级

下载 `VRC-Bili-Relay-0.1.30-windows-x64.zip`。关闭旧程序，完整解压到新的空文件夹后运行；保留旧版文件夹便于回退。设置和登录信息的存储格式未改变。

发布流程重新下载上传的 ZIP，核对 SHA-256，再把同一份字节解压到构建机 `release/`；`RELEASE-VERIFICATION.json` 记录结果。不会远程关闭或替换你电脑上正在运行的程序。

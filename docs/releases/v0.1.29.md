## v0.1.29 — 媒体时间轴、弹幕与推流契约修复

这一版继续修复 v0.1.28 尚未改动的 Rust 媒体链路，不改 UI 布局、不重写编解码器，也不靠扩大缓冲或超时时间掩盖问题。v0.1.28 的 worker 通信修复保留。

### 修复

- **统一进程切换与时间轴收尾**：暂停、恢复、跳转和倍速共用生产进程的退出/进度收集流程。旧进程退出后先收齐最终可用进度，再推进内部时间戳；失败的新进程即使已经输出部分媒体，也走相同的收尾路径。恢复不再仅凭“进程创建成功”判定成功，而是等待实际输出。外层 RTMP publisher 仍由同一会话持有。
- **明确音视频输出契约**：解析器明确区分独立音轨、内嵌音轨和已确认无音轨。无音轨点播源补入静音，所有正常生产进程保持 H.264 / AAC 双音视频流；点播音频补齐但以视频结束为准，避免静音源无限运行；该结束约束也适用于无时长、被归类为直播的补静音源。画面按显示宽高比归一化为偶数尺寸与方形像素。
- **正确声明 MPEG-TS 生产进程边界**：每次新生产进程启动声明 initial discontinuity，避免只延续时间戳却没有声明 TS 连续计数器重置。
- **修复弹幕的多层转义**：ASS 路径、滤镜图和 ZMQ 动态命令使用统一的语法层处理，支持包含单引号、空格、冒号、方括号等字符的路径和文字；不通过 shell 执行。
- **直播弹幕使用实际帧时钟**：运动和自过期从首次真正绘制的帧开始，不再把线程墙钟当成 FFmpeg 帧时间；720p/1080p 的字号与位置按画面尺寸缩放，底部文字考虑自身高度。未确认清除的槽位不会被当作空闲槽位复用。
- **修复状态与资源归属**：重复暂停/恢复不再替换实际生产进程使用中的 ASS 文件；已观测位置不再被“跳转时避开最后一秒”的策略截断。倍速变更先预取弹幕，再重新读取仍在推进的视频位置。

### 实测与证据

发布前执行 Windows 构建、TypeScript 检查、真实 worker 往返基准，以及 Windows/Linux 的本地媒体基准。基准调用实际 Rust 生产进程和滤镜实现，使用合成视频、回环 HTTP/RTMP 和 FFprobe；弹幕直接统计真实输出像素，而不把命令成功当成文字已出现。

验证过程曾抓到初版补丁在 Windows FFmpeg 9.0.2 下因重设非运行时选项 `expansion` 而拒绝整条弹幕命令。该补丁未发布：初始化策略与动态参数分离后，重新采集相同的画面数据。

发布附件包含 `media-pipeline.json`、`ffmpeg-toolchain.json`、`worker-roundtrip.json`、ZIP 校验文件和 `RELEASE-VERIFICATION.json`。详见仓库 `docs/media-pipeline-audit.md`，其中区分原有缺陷、修复中捕获的回归、实际观察与未验证范围。

**限制**：这些是本地合成媒体观察，不是用户账号、真实 Bilibili/VRCDN 服务或 VRChat 世界的端到端验收。进程切换仍可能有短间隔；强制终止可能缺少最终进度。暂停保持的是生成的提示画面，并不是截取视频最后一帧。本版不宣称解决所有弹幕字体差异、滚动弹幕碰撞或远端缓冲问题。

### Debug 数据

默认目录仍为 `%LOCALAPPDATA%\VRC Bili Relay\runtime\diagnostics`。

`relay-health.jsonl` / `relay-health.previous.jsonl` 增加媒体切换事件：publisher/producer PID、桥接时间戳、源位置、倍速、暂停/结束状态、输出尺寸；直播弹幕记录收到的事件、槽位容量丢弃、命令确认/未确认和耗时。配合 `worker-rpc.jsonl` / `worker-rpc.previous.jsonl`，可区分 UI 排队、Rust 执行、媒体输出与弹幕命令问题。`dropped_records` 非零表示证据可能不完整。

日志有大小和队列上限，不默认写入 Cookie、推流密钥、上游媒体地址或弹幕正文。复现后保留上述文件及操作时间、程序版本和 FFmpeg 版本，不需要提供账号凭据。

### 下载与升级

下载 `VRC-Bili-Relay-0.1.29-windows-x64.zip`，关闭旧程序后完整解压到新的空文件夹运行。设置和登录存储格式不变。FFmpeg 仍是外部程序；测量用 FFmpeg 不会被捆绑进便携包，也不会替换用户已安装的版本。

发布流程重新下载已上传的 ZIP，核对 SHA-256 后将同一文件解压到构建机 `release/`。不会远程关闭或替换用户桌面上的程序。

## v0.1.28 — Worker 生命周期与可观测性修复

本次修复集中在 UI ↔ Rust worker 的共享通信边界，不修改 UI 布局、弹幕绘制、媒体时间轴或 FFmpeg 推流参数。

### 修复

- 将串行 Rust worker 对应的命令调度统一为有界 FIFO：尚未发送的排队时间与真正发送后的执行等待时间分别记录，避免前一个慢请求消耗后续请求的执行期限。
- 协议握手按 worker 进程代次共享，不再为每个业务操作重复排队一个 health 请求；显式 health 查询仍读取最新 FFmpeg 安装状态。
- 请求一旦已经发送后超时或协议损坏，不再只是删除 Promise 后放任后台执行；终止该 worker 代次，不自动重试。旧进程退出前不启动替代进程，避免状态不明和重复推流。
- 读取 stderr 改为实时、有界逐行处理；不再一直缓存在内存直到 worker 退出。
- 请求/响应加入读取时的大小限制、回复类型与请求编号校验，处理异步 stdin flush 失败。
- 关闭期限覆盖 shutdown 回包与实际进程退出，清理尚未发送的请求，避免收到回包后仍无限等待。

### Debug 数据

默认记录于 `%LOCALAPPDATA%\VRC Bili Relay\runtime\diagnostics`：

- `worker-rpc.jsonl` / `worker-rpc.previous.jsonl`：请求编号、命令名称、进程代次、排队耗时、UI 往返耗时、Rust 执行耗时、字节数、错误码与退出事件。
- 原有 `relay-health.jsonl` / `relay-health.previous.jsonl`：FFmpeg producer/publisher 数值进度与告警分类。

不会默认写入 Cookie、推流密钥、媒体链接、完整请求参数或错误正文。日志有容量与队列上限；`dropped_records` 表示证据可能不完整。问题重现后复制上述文件，附上操作时间与程序版本即可分析，不需要先提供账户凭据。

### 架构与验证

通信调度、字节分帧、诊断写入已拆成独立模块；`worker-client.ts` 仍是唯一 UI 进程适配器，Rust core 仍负责媒体规则。根因分析与证据要求已写入 `AGENTS.md`，详细说明见 `docs/worker-transport-audit.md`。

发布流程执行 Windows 构建、TypeScript 检查与真实本地 worker 往返基准，随附 `worker-roundtrip.json`。这是性能与诊断数据，不是 VRChat/Bilibili/VRCDN 的端到端验收。没有在用户的登录环境或 VRChat 世界内进行验证，也没有执行功能测试套件。

重要行为：真正发生“已发送命令超时”时会停止当前 worker 及其受管子进程，因而活动中继也会停止；这是明确终止未知状态，而不是悄悄重试。核心仍同步执行任务，本次不承诺消除慢网络操作本身造成的等待。

### 下载与升级

下载 `VRC-Bili-Relay-0.1.28-windows-x64.zip`，关闭旧程序后解压到新的空文件夹运行；设置和登录状态仍由原有本地存储管理，本次未改变存储格式。

发布 ZIP 上传后会重新下载并核对 SHA-256，再将同一份上传文件解压到构建机的 `release/`；`RELEASE-VERIFICATION.json` 记录提交与校验结果。不会远程关闭或替换用户桌面上正在运行的程序。

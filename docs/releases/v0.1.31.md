## v0.1.31 — UI 会话归属、账号缓存与保存修复

保留 v0.1.30 的媒体和 ASS 时钟修复。这版按上一轮审查顺序处理五组 UI/后台边界问题，不重写媒体参数、不改变 UI 布局或本地设置格式。

### 修复

1. **播放任务与资源归属**：生成、恢复、切换、暂停、倍速、停止及状态轮询使用同一播放流程管理器。过期启动先记录其真实会话归属，再按会话和 worker 代次清理；新任务在清理结束后才可派发。
2. **失败恢复不再靠猜**：只在同一仍存活 worker 返回实际状态后显示原内容仍在播放。worker 退出会使旧状态失效，旧会话查询不会悄悄启动新 worker。
3. **视频库账号隔离**：缓存和未完成请求绑定认证作用域；退出/重新登录立即撤销，旧账号迟到结果不能填回缓存。缓存新增容量上限。
4. **封面队列不再被失败项堵住**：失败项完成本轮尝试，让后续封面继续；每项最多三次尝试。Rust 下载增加 2 MiB 读取上限、临时文件清理和数值失败分类。
5. **设置快照与退出顺序**：旧保存回包只确认对应字段版本，不覆盖保存期间继续输入的内容。应用内关闭按钮先提交自动偏好和等待已提交保存；超时或失败则取消关闭，保留窗口和 worker。

### 行为与限制

如果过期推流会话无法确认清理，程序会终止对应 worker 代次，而不是继续保留未知推流或重试播放；活动中继可能因此停止，需要重新生成。

退出时设置提交超过五秒会取消退出，而不是放弃保存。手动设置草稿仍需点击保存；本次没有为所有系统原生退出路径建立拦截，Alt-F4/关机/强制结束等不属于已验证的保存保证。

### Debug 与测量

日志仍在 `%LOCALAPPDATA%\VRC Bili Relay\runtime\diagnostics`。新增 UI 操作编号、会话归属/失效事件、账号缓存作用域代次、设置提交版本和封面失败分类。默认不记录账号 ID、Cookie、密钥、链接、弹幕正文或设置内容。日志有容量上限；`dropped_records` 非零表示证据不完整。

新增 `ui-state.json` 随 Release 提供。UI 调度/缓存/封面/保存测量使用生产模块与明确的模拟延迟/故障，另有真实编译 worker 的退出/换代观察；原有 worker 往返、本地 FFmpeg 媒体与 ASS 回滚测量保留。这不是原生窗口、真实换号、CDN、Bilibili/VRCDN/VRChat 的端到端验收。

审查、数据和限制见 `docs/ui-state-audit.md`。本次不声称全仓结构 bug 已清零。

### 下载

下载 `VRC-Bili-Relay-0.1.31-windows-x64.zip`。关闭旧程序后完整解压到新文件夹运行。发布流程重新下载并核对实际上传 ZIP 的 SHA-256，`RELEASE-VERIFICATION.json` 保存对应提交与校验结果；不会远程替换用户电脑上正在运行的程序。

# v0.1.34 — Bounded commands and best-effort danmaku

Protocol 26: the UI and `relay-worker.exe` from this archive must be used together.

## Fixed

- A slow Bilibili response no longer stops a running relay. Every command's
  network requests share one time budget, and every UI deadline exceeds that
  budget plus FFmpeg's startup wait (table in `docs/worker-transport-audit.md`).
- Danmaku failures no longer prevent playback. Video segments download four at a
  time within 10 seconds; when preparation fails the relay starts without
  danmaku and the status line says so. Partial danmaku is not cached as complete.
- VOD danmaku backslashes render once (`\(^o^)/`), and `\N`, `\n`, `\h` in
  comments no longer break lines.
- Live danmaku checks the websocket auth reply, fetches a fresh token after a
  rejection or three failed connections, and records each disconnect as a
  numeric diagnostic event.
- An unparseable request fails only that call instead of restarting the worker.
- `live.bilibili.com/blanc/{room}` and `/h5/{room}` links are accepted; a regular
  CDN host is preferred over mcdn within the chosen live codec.
- Region/permission restrictions (-403/-10403) are reported as such instead of
  asking the user to log in. Expired logins can be replaced by scanning again.
- Local-network media URLs (single-label hosts, `.lan`/`.local`, CGNAT, mapped
  IPv6) are relayed instead of handed to VRChat directly.
- FFmpeg output readers survive non-UTF-8 bytes; the filter capability probe has
  a 5-second limit.
- Settings and login writes are safe with two instances running; unreadable
  settings can be replaced by saving; settings from a newer version are never
  overwritten. Cover cache keeps on-screen thumbnails and rejects non-images.
- UI: finishing a conversion no longer leaves Settings and discards edits; a
  failed settings read is retried and reported; Copy only copies real URLs, as
  UTF-8; “跟随系统” follows the Windows app theme; a failed “load more” keeps
  loaded rows; seek drags interrupted by playback updates are cancelled; Back
  after a cancelled close returns to the running relay; colors live in
  `src/theme.ts`.
- Error messages no longer include request URLs (QR login key, account ids).

## Evidence

Linux: `cargo clippy`, `bun run typecheck`, and the worker round-trip,
liveness, state-boundary and UI-state benchmarks ran against the new worker
(handshake protocol 26, 768 round trips, no errors). The Windows workflow builds,
type-checks, packages and re-runs every release measurement; the uploaded ZIP is
re-downloaded, SHA-256 verified and expanded from those exact bytes.

Not verified: real Bilibili/VRCDN/VRChat playback, the PowerShell clipboard and
registry theme reads on Windows, live danmaku token refresh against the service,
and native-window behavior. AI-assisted implementation and review.

# v0.1.33 — Playback polling and search pagination

## Fixed

- Keep observing an owned active relay after a new conversion is cancelled while
  an earlier status reply is pending. A discarded reply no longer ends the loop.
  Polling follows session ownership, remains serialized and generation-pinned,
  and stops for terminal sessions or disposed views.
- Bind search results and load-more requests to the same immutable query. Keyword
  and folder-scope edits invalidate old responses immediately; the unchanged
  debounce delays only dispatch. Late replies cannot enable mixed-query pages.

## Evidence

Windows/Linux workflows build/type-check and retain `liveness.json`, alongside
existing UI, session-boundary, real-worker, local-media and ASS reports. The new
measurements use actual production modules/extracted handlers with explicit
virtual timers and simulated backend responses, not a native-window or live-
service acceptance run. Details and local before/after controls are in
`docs/liveness-audit.md`. Reports identify the exact revision they measured.

The uploaded Windows ZIP is re-downloaded, SHA-256 verified and expanded from
those exact bytes; `RELEASE-VERIFICATION.json` records the correspondence.

Media clocks, codecs, FFmpeg options, polling/debounce intervals, protocol,
settings and login formats are unchanged. Real Bilibili/VRCDN/VRChat behavior and
all native window-close paths are not newly verified. Existing bounded-log drops
and local RTMP recorder teardown warnings retain their documented limitations.
